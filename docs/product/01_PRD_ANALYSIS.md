## 2. 구현을 시작하려고 둔 가정

PRD §8 질문 3개(Q1~Q3)의 답을 기다리느라 기반 골격 작업을 멈추지 않는다. 아래 가정을 화면과 코드에 드러내 두고 시작한다.

| PRD 질문 | 가정 | 바뀔 때 영향 |
|---|---|---|
| Q1 첫 사용자·형식 | **[가정]** 개인 일기, 짧은 글 중심. 사진은 나중에 붙일 수 있게 자리만 둔다 | 사진을 넣으면 버킷 연결과 업로드 검증 단계를 추가한다 |
| Q2 하루 정리 방식 | **[가정]** (A) 사용자가 직접 쓴다. 외부 AI로 보내는 것은 없다 | B를 고르면 동의·전송 설계 뒤 초안 기능을 추가한다(정리 화면 구조는 유지) |
| Q3 공유 범위 | **[가정]** 비공개가 기본이며 본인만 본다 | 공유를 고르면 권한 모델을 추가한다. 소유자 열(`user_id`)은 이미 있다 |

## 3. 빈칸과 위험

- 인증 공급자·로그인 방식 [미정]: 실제 로그인, 첫 로그인 지급, 다중 기기 접근이 여기에 달려 있다.
- 일기 데이터의 민감성: 외부 전송(인증 공급자로 가는 식별 정보, AI), 백업·삭제 정책이 [미정]이다.
- 꾸미기 Lite의 펜 데이터 크기와 반응형 배치: 상한과 정규화 좌표로 대응한다([02_SHAPING](02_SHAPING.md) §3).
- PRD의 성공 기준(1~2주 사용, 주 1회 회상)은 측정 방법이 [미정]이다. MVP에 분석 도구는 넣지 않는다.
