## 2. 핵심 해석과 남은 가정

사진·메모·시간 기반 AI 이야기는 포함 여부를 다시 선택할 대상이 아니다. 세부 동작은 아래 미정을 해결한 뒤 설계한다.

| 항목 | 현재 해석 | 설계에 필요한 것 |
|---|---|---|
| 사진·짧은 메모 | **[확정]** AI 하루 이야기의 입력 재료 | 장수·용량·길이·필수 입력 여부, 실제 업로드·보관·접근 검증 |
| 회고 시각 | **[확정]** 사용자 메뉴 → 설정에서 하루 회고 시각 선택. 초기 기본 **20:00(저녁 8시)**, 사용자 변경 가능. 개별 사진·메모의 원본 기록 시각과 구분 | **[구현 제안]** PC·휴대폰 설정 화면, 같은 계정에 설정 저장·재접속 조회. 정한 시각을 회고 경험의 기준으로 쓰며 자동화·알림 전달 방식은 후속 설계 |
| AI 하루 이야기 | **[확정]** AI가 하루의 스토리텔링을 만듦 | 제공자·모델, 전송·동의·보관·학습 조건, 사진 분석 범위, 비용·생성 트리거 |
| 결과를 다시 읽기 | 날짜별로 AI 이야기와 원래 조각을 읽는 흐름이 필요 | **[권고]** 결과를 보관. 수정·재생성·폐기 동작은 제안·검토 단계 |
| 첫 사용자·공유 | **[가정]** 운영자 본인을 첫 검증 사용자로, 본인만 보기로 시작 | 서비스 대상·공유 범위 확인. 공급자 간 계정 연결도 미정 |

### 2.1 초기 가정의 이력

2026-11-02 초기 문서는 ‘짧은 글 중심, 사진은 나중’, ‘하루 정리는 직접 작성’을 기반 작업용 가정으로 두었다. 후속 기획에서 사진·AI가 제외 범위로 좁아졌지만 사용자 거부·제외 승인으로 보지 않는다. 2026-11-10 교정 이후의 제품·MVP 범위에는 적용하지 않는다. 기존 직접 작성 한 줄은 보조 기록이다.

## 3. 빈칸과 위험

- 실제 사진·AI·시간 흐름의 화면이 없다. 기존 D 테마는 유지하되 AI 회고 아트보드와 실패·빈 상태를 앞으로 설계해야 한다. SVG 예시 이미지는 실제 사진 업로드가 아니다.
- 로그인 공급자는 Google·Kakao로 확정됐다. 실제 인증·서버 저장의 사용자 제공과 PC↔휴대폰 재조회 검증은 기반 작업으로 연결한다.
- 일기 데이터의 민감성: AI 외부 전송 동의·전송 범위·보관·학습 사용 여부, 백업·삭제 반영 세부가 미정이다. AI 핵심 요구만으로 외부 전송에 동의했다고 간주하지 않는다.
- 생성 결과의 사실성·문체·누락, 실패·지연·중복 생성 대응은 수용 기준으로 구체화해야 한다. 회고 시각 설정은 확정됐으며, 자동화·알림 전달 방식·수정·재생성 규칙과 출시 시한은 후속 설계·미정이다.
- 꾸미기 Lite의 펜 데이터 크기와 반응형 배치: 상한과 정규화 좌표로 대응한다([02_SHAPING](02_SHAPING.md) §3).
- PRD의 성공 기준(1~2주 사용, 주 1회 회상)은 측정 방법이 미정이다. AI 하루 이야기로 실제 회고할 수 있는지가 먼저 확인되어야 한다.
