# 03 MVP 정의

- 입력: [02_SHAPING](02_SHAPING.md), [PRD](../PRD.md) §0·§9. 2026-11-10 사용자 교정을 반영한 핵심 계획은 [PLAN_ai-daily-story-core](../plans/PLAN_ai-daily-story-core.md)다.
- [PLAN_mvp-foundation](../plans/PLAN_mvp-foundation.md)과 [PLAN_product-evolution](../plans/PLAN_product-evolution.md)의 기존 직접 작성 중심 단계는 기반 구현 이력이다. 사진·AI를 제외한 당시 기준만으로 현재 MVP 완료를 판단하지 않는다.
- **현재 미구현:** 실제 사진 업로드·AI 하루 이야기·설정된 시간 기능. 기존 로그인·메모 저장은 필요한 기반이며 제품 핵심의 완료가 아니다.

## 1. 범위

| 포함 [확정] | 후속 또는 별도 결정 |
|---|---|
| **사진·메모 몇 줄·시간을 바탕으로 AI가 하루의 스토리텔링을 만듦**(2026-11-10 핵심 확정) | 마켓 게시·구매, 사용자 간 정산, 감정덩어리 현금화 |
| 실제 사진 업로드·저장, 조각 작성·수정·삭제, AI 이야기와 원래 조각의 날짜별 다시 읽기 | 영상·음성 등 사진 외 미디어(제외 제안) |
| ‘설정된 시간’을 회고에 반영. 의미는 순간별 시각 / 매일 생성 시각 / 둘 다 중 **[미정]** | 자동 생성 트리거·스케줄·알림은 포함을 확정한 것이 아님 |
| 사용자 폰트 선택(기록 본문) | 전문 드로잉 도구, 본인 그림 업로드(포함 여부 [미정]) |
| 개인용 하루 꾸미기 Lite | 감정덩어리의 다른 사용처 |
| 실제 로그인을 도입할 때 첫 성공 로그인 10개 지급(계정당 1회) | 공유(범위 미정) |
| **Google·Kakao 로그인 둘 다**(2026-11-03 확정) | 공급자 간 계정 연결 방식([미정], 사용자 답변 대기) |
| **PC·휴대폰 모두**에서 계정 자료 접근·다시 읽기(2026-11-10 확정) | AI 제공자·모델·가격·외부 전송 동의는 별도 미정 |
| **계정 탈퇴: 30일 복구 기간 → 삭제**(2026-11-03 사용자 확정). 요청 즉시 접근 차단과 명시적 복구 확인은 메인 기술·UX 결정([PLAN_account-lifecycle](../plans/PLAN_account-lifecycle.md)) | 개별 조각 삭제의 보관 기간(현행 즉시 삭제 유지, 30일 정책은 계정 단위) |

별도 결정 항목은 AI 하루 이야기의 포함 여부를 미루는 뜻이 아니다. 실제 연결과 동작을 설계하기 위한 세부 조건이다.

**[권고] 최소 수직 슬라이스:** 실제 계정에 사진을 업로드·저장 → 짧은 메모·시간 입력 또는 설정(시간 의미 확인 뒤 구체화) → AI 하루 이야기 생성·읽기 → 재접속해 날짜별로 이야기와 원래 조각 다시 읽기. 결과 보관 방식·사용자 수정·재생성·폐기는 설계 제안 단계이며 명시적으로 결정한다. 직접 쓰는 한 줄은 보조 기록으로 유지하는 제안이며 AI 생성의 대체물이 아니다.

## 2. 감정덩어리: 정책과 구현 시점

- **정책 [확정]:** 계정(canonical `user_id`)당 한 번, 첫 성공 로그인에 10개를 지급한다. 디자인 구매에는 1개를 쓴다.
- **지급과 구매는 별개 기능이다.** 지급은 MVP에 넣고, 구매는 후속 마켓 단계에서 넣는다.
- **구현 추천:** 실제 로그인을 도입하는 PR에 **append-only grant 원장 최소형을 함께 넣는다.**
  - 구성: `credit_accounts`, `emotion_ledger`, `grant_key` 유일 제약.
  - 이렇게 하면 로그인한 사용자가 지급 없이 쌓이는 기간이 생기지 않는다.
  - 소급 지급 경로는 예외 상황용으로만 남긴다.
- 제작자 +1 시점(구매자별 첫 구매 기준)은 권고다. 현금화·정산은 미정이다.

## 3. 기반 구현과 핵심 흐름의 의존성

| 작업 묶음 | 별도 의존성 |
|---|---|
| 계정·인증·기록 저장 기반 | 실제 로그인 공급자 Google·Kakao 확정. 계정 연결 답변과 [인증 계획](../plans/PLAN_mvp-authentication.md)·[계정 수명주기 계획](../plans/PLAN_account-lifecycle.md), 실제 배포 검증으로 연결 |
| 실제 사진 저장과 짧은 메모 | 이미지 저장소 공급자·접근·용량·보관·삭제, 계정별 권한, 업로드 실패·재조회 기준 |
| 시간 입력·설정 | ‘설정된 시간’의 의미 확인. 확인 전 스케줄러·자동 생성·알림 도입을 확정하지 않음 |
| AI 하루 이야기 | 제공자·모델·사진 분석 범위·전송 동의·보관·학습 조건·비용, 생성 시작·실패 처리 설계 |
| D 기반 회고·날짜별 읽기 UI | 사진·시간·생성 전/중/실패/완료·이야기 읽기 아트보드는 아직 없음. 기존 한 줄 화면으로 완료 처리하지 않음 |
| 꾸미기 Lite·기록 글꼴 | 기존 확정 범위 유지, 폰트·스티커 라이선스 확인 |
| 서버 DB·버킷, 앱 배포 전환 | 메인·비공개 런북·배포 프로그램 검토. 문서 정렬은 서버 변경·외부 전송 권한을 추가하지 않음 |

## 4. 완료 판단

[PRD](../PRD.md) §9와 [핵심 계획](../plans/PLAN_ai-daily-story-core.md)을 기준으로 세부 수용 기준을 구체화한다. 최소한 다음 전체가 이어져야 한다.

- [ ] 예시 SVG가 아닌 실제 사진을 계정에 업로드·저장하고 재접속해 다시 조회한다.
- [ ] 짧은 메모와, 의미를 확인한 시간 정보를 기록·회고에 반영한다.
- [ ] 결정된 데이터·비용 조건으로 실제 AI가 하루 이야기를 만들고 사용자가 읽는다. 사진 분석·생성 동작 세부는 결정 뒤 검증한다.
- [ ] 날짜를 골라 AI 하루 이야기와 원래 사진·메모를 다시 읽는다. PC·휴대폰과 같은 계정의 다른 기기에서 확인한다.
- [ ] 조각 수정·삭제, 기록 글꼴, 개인용 꾸미기 Lite 등 기존 확정 범위를 검증한다.
- [ ] 실제 인증의 소유자 접근, 첫 성공 로그인 10개 1회 지급, 탈퇴 30일 복구 뒤 삭제를 각 계획 기준으로 검증한다.

로그인 성공, 텍스트 CRUD, 직접 쓰는 하루 한 줄, 정적 시안·브라우저 체험판만으로는 이 MVP를 완료하지 않는다. 출시 시한은 미정이다.
