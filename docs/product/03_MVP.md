- 입력: [02_SHAPING](02_SHAPING.md). 실행: [PLAN_mvp-foundation](../plans/PLAN_mvp-foundation.md). 단계 전체: [PLAN_product-evolution](../plans/PLAN_product-evolution.md) §1(수용 기준 정본).

## 1. 범위

| 포함 [확정] | 제외(후속) |
|---|---|
| 조각 작성·수정·삭제, 한 줄 정리, 날짜별 보기 | 마켓 게시·구매, 사용자 간 정산, 감정덩어리 현금화 |
| 사용자 폰트 선택(기록 본문) | 전문 드로잉 도구, 본인 그림 업로드(포함 여부 [미정]) |
| 개인용 하루 꾸미기 Lite | 감정덩어리의 다른 사용처 |
| 실제 로그인을 도입할 때 첫 성공 로그인 10개 지급(계정당 1회) | AI 초안·공유·사진(PRD Q1~Q3 답 전) |

## 2. 감정덩어리: 정책과 구현 시점

- **정책 [확정]:** 계정(canonical `user_id`)당 한 번, 첫 성공 로그인에 10개를 지급한다. 디자인 구매에는 1개를 쓴다.
- **지급과 구매는 별개 기능이다.** 지급은 MVP에 넣고, 구매는 후속 마켓 단계에서 넣는다.
- **구현 추천:** 실제 로그인을 도입하는 PR에 **append-only grant 원장 최소형을 함께 넣는다.**
  - 구성: `credit_accounts`, `emotion_ledger`, `grant_key` 유일 제약.
  - 이렇게 하면 로그인한 사용자가 지급 없이 쌓이는 기간이 생기지 않는다.
  - 소급 지급 경로는 예외 상황용으로만 남긴다.
- 제작자 +1 시점(구매자별 첫 구매 기준)은 권고다. 현금화·정산은 미정이다.

## 3. 지금 시작할 수 있는 것과 따로 기다리는 것

| 지금 가능(사용자 승인 스택·D, §01의 가정을 드러낸 채) | 별도 의존성 |
|---|---|
| Next.js 앱 골격, 패키지 설치와 버전 고정(호환 확인 후) | 실제 로그인: 인증 공급자·방식 결정 |
| D 화면 이식, 오늘·모아보기·작성·설정 UI | 외부 AI 전송: PRD Q2 B 선택과 동의 설계 |
| 도메인 모듈과 저장 port(메모리 구현 + PostgreSQL 구현), TDD | 공유: PRD Q3 |
| 로컬·CI 컨테이너 PostgreSQL 18로 migration·권한 테스트 | 서버 dev/prod DB·버킷 생성: 메인·비공개 런북 |
| 꾸미기 Lite 편집기·렌더러·fallback | 앱 배포 전환: 배포 프로그램 검토(메인) |
| 로컬·테스트 전용 고정 사용자 | 폰트·스티커 라이선스 확인 |
