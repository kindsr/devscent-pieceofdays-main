# 04 스토리보드 — AI 하루 이야기 경험 초안

- 상태: **경험 초안, 2026-11-10 정렬.** 사진·메모 몇 줄·설정된 시간으로 회고하며 AI가 하루 이야기를 만드는 것은 사용자 교정으로 확정됐다. 아래는 앞으로 설계할 경험이며, AI 회고 아트보드나 구현 완료를 뜻하지 않는다.
- 근거: [PRD](../PRD.md) §0·§4·§7·§9, [AI 하루 이야기 핵심 계획](../plans/PLAN_ai-daily-story-core.md). 시각 방향은 기존 D 선택을 따른다.
- 회고 시각 **[확정]**: 사용자 메뉴 → 설정에서 하루를 회고할 시각 선택. 초기 기본 **20:00(저녁 8시)**, 사용자 변경 가능. 사진·메모의 원본 기록 시각 입력·수정 요구와 구분한다.
- 미정·후속 설계: AI 제공자·전송 동의·사진 분석·비용, 회고 시각에 맞춘 자동화·알림 전달 방식, 결과 수정·재생성·보관 동작 세부, 공유 범위.
- 이력: 2026-11-02 시안 비교용 흐름은 짧은 글·사진 선택·직접 쓰는 하루 정리를 가정했다. 그 가정은 당시 시안 설명이며 현재 제품 핵심이나 AI 제외 승인으로 쓰지 않는다. 실제 사진 업로드·AI 생성·설정된 시간 기능은 미구현이다.

## 1. 대표 흐름

| 장면 | 사용자 상황 | 화면 | 주 동작 | 끝난 상태 |
|---|---|---|---|---|
| S0 첫날 | 긴 일기를 쓰지 않고도 하루를 남기고 싶다 | 빈 상태(압박 없는 안내) | 사진·짧은 메모 남기기 | 기록 시작. 입력 필수 여부는 설계 필요 |
| S1 순간 기록 | 점심에 국수를 먹은 사진과 메모 몇 줄을 남긴다 | 실제 사진 입력·메모 작성 | 사진 업로드·기록 | 실제 사진과 메모가 계정에 남음. 실패 시 안내 필요 |
| S2 회고 시각 설정 | 내 하루를 돌아볼 시각을 고르고 싶다 | 사용자 메뉴 → 설정 | 기본 20:00 확인·변경 | 정한 시각이 회고 경험의 기준. **[구현 제안]** 같은 계정에 저장·재접속 조회 |
| S3 AI 회고 | 긴 글을 직접 완성하지 않고 하루의 이야기를 보고 싶다 | 생성 전·진행·실패·완료 상태 | AI가 하루 이야기 생성(시작 방식 미정) | 사진·메모·시간을 바탕으로 만든 이야기를 읽음 |
| S4 이야기 확인 | AI 이야기를 통해 그날을 돌아본다 | AI 이야기와 원래 조각 | 읽기. 수정·재생성 동작은 제안 단계 | **[권고]** 날짜별로 다시 읽을 결과를 보관 |
| S5 다시 읽기 | 며칠 뒤 지난 하루가 궁금하다 | 날짜 목록/달력 → 그날의 이야기와 조각 | 날짜 선택 | PC·휴대폰에서 같은 계정의 AI 이야기·원래 사진·메모를 다시 읽음 |

직접 쓰는 ‘하루 한 줄’은 보조 기록으로 다루며 S3·S4의 AI 회고를 대신하지 않는다. 회고 시각은 정했으며, 자동화·알림 전달 방식은 후속 설계다.

## 2. 기존 시안 비교용 샘플 하루 (2026-11-02 이력)

- 오늘: 2026년 11월 2일 월요일 — 순간 4개(07:40 창가, 12:15 국수, 16:30 은행나무 길, 21:10 엄마와 통화), 하루 정리 1개.
- 지난 날: 11월 1일(일, 순간 2·정리 있음), 10월 30일(금, 순간 1·정리 없음), 10월 28일(수, 순간 3·정리 있음).
- 기록 없는 날은 표시를 비우거나 흐리게만 한다. 경고·연속 기록 압박을 두지 않는다.
- 샘플 이미지 3종은 직접 그린 SVG이며 "예시 이미지"로 표시한다. 실제 사용자 사진 업로드·보관·AI 사진 분석이 아니다.
- 위 ‘하루 정리’는 당시 직접 작성 시안의 예시다. AI 생성 결과 예시나 새 AI 아트보드가 아니다.

## 3. 설계할 핵심 상태 (아트보드·구현 미완료)

| 화면 | 기본 | 빈 상태 | 오류·제한 |
|---|---|---|---|
| 사진·메모 작성 | 실제 사진 입력과 짧은 메모 | 사진·메모가 없는 상태, 입력 기준 안내 | 업로드·저장 실패와 재접속 상태. 용량·장수·필수 여부 미정 |
| 회고 시각 설정 | 사용자 메뉴 → 설정, 기본 20:00·사용자 변경 가능 | 초기 기본값 표시 | **[구현 제안]** PC·휴대폰 설정 저장·재접속 조회. 원본 기록 시각과 구분하고 시간대 등 기술 세부는 후속 설계 |
| AI 하루 이야기 | 생성 전 → 진행 → 결과 읽기 | 조각 없음 / 아직 생성되지 않음 | 외부 전송 조건, 생성 실패·지연·중복, 사진 분석 범위·재생성 규칙 미정 |
| 날짜별 다시 읽기 | AI 이야기와 원래 사진·메모 | 기록 없는 날, 생성 결과가 없는 날 | 자료 조회 실패·기기 간 재조회 검증 필요 |
| 보조 한 줄·글꼴·꾸미기 | 기존 확정 기능을 함께 제공 | 기존 D 방향을 이어 사용 | AI 이야기와 보조 한 줄의 역할을 구분하고 새 배치를 설계 |

기존 D 아트보드의 글 필수·예시 이미지 선택·직접 정리 편집과 메모리 초기화 동작은 [핸드오프](../design/README.md)의 역사·시안 범위다. 이 표의 실제 사진·AI 상태를 이미 그렸거나 구현했다고 해석하지 않는다.

## 4. 남은 질문

1. AI 제공자·모델·전송/동의·보관/학습·사진 분석·비용 조건과 생성 시작·결과 편집 동작은 어떻게 정할 것인가?
2. 첫 사용자와 공유 범위는 어디까지인가?

사진·AI의 포함 여부를 다시 고르는 질문은 두지 않는다. 답변과 핵심 계획을 바탕으로 실제 사진·시간·AI 회고 화면을 D 방향으로 설계하고 검토해야 한다.
