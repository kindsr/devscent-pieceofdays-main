## 2. 제품 정의

- **[확정]** "개인의 일상에서 순간을 기록하고 하루를 정리하여 스토리텔링을 만들어가는 감정정리 장소, pieceofdays".
  개인이 하루 중 "순간"을 기록하고, 그 순간들로 "하루"를 정리해, 시간이 지나며 이야기로 쌓아 가는 곳이다.
  (이력: 첫 초안의 "…일기장" 소개를 2026-11-02 "감정정리 장소"로 바꿨다. 기록·정리·스토리텔링의 흐름은 같다.)
- **[권고]** 핵심 단위 3개: 순간(작은 기록 조각) → 하루(그날 순간의 정리) → 이야기(날짜를 따라 쌓인 하루들).
- **[권고]** 차별점 가설: 하루를 한 번에 길게 쓰는 부담 대신, 낮은 부담으로 조각을 남기고 저녁에 묶는다.

## 4. 권고 핵심 여정: 순간 기록 → 하루 정리 → 날짜별 다시 보기

| 단계 | 사용자 행동 | 결과 |
|---|---|---|
| 1. 순간 기록 | 오늘 화면에서 짧은 글(+선택 사진)을 저장 | 시각이 붙은 순간이 오늘에 쌓임 |
| 2. 하루 정리 | 오늘의 순간들을 보며 하루 요약을 작성(방식은 §7 A/B 결정 대기) | 그날의 "하루" 기록 생성·수정 가능 |
| 3. 날짜별 다시 보기 | 달력/날짜 목록에서 날짜를 골라 하루 정리와 순간을 다시 읽음 | 지난 기록 회상 |

## 5. 최소 수직 슬라이스 후보와 첫 화면 후보

**[권고] 최소 수직 슬라이스:** 1인 사용자가 순간(글만) 2개를 저장 → 하루 정리를 직접 작성·저장 → 다음 날 날짜를 골라 둘 다 다시 본다. 사진·AI는 이 슬라이스가 동작한 뒤 붙인다(사진은 Q1 답에 따라 슬라이스에 포함 가능).

| 첫 화면 후보 | 내용 | 장점 | 위험 |
|---|---|---|---|
| **(권고) 오늘** | 오늘의 순간 목록 + 기록 입력 + "하루 정리" 진입 | 기록 부담이 가장 낮고 여정 1·2와 직결 | 회상 가치가 첫눈에 덜 보임 |
| 달력 | 월 달력에 기록 있는 날 표시 | 회상·쌓임이 보임 | 첫 사용 시 빈 화면, 기록까지 한 단계 더 |

화면 구성(오늘·달력·돌아보기 + 작성 액션)은 조사 문서의 잠정 제안이며 시안 비교 대상이다.

## 6. MVP 제외 제안

**[확정]** MVP에 넣는다: 기록 CRUD(조각 추가·개별 수정·삭제, 하루 정리), 기록 글꼴 설정, 개인용 하루 꾸미기 기본(간단한 그리기·안전 영역 안 배치).
**[확정]** 후속: 디자인 마켓·구매·제작자 정산. 첫 로그인 감정덩어리 지급 정책은 §0을 따르고, 지급 구현 단계와 마켓 사용 단계를 계획에서 구분한다.

**[권고]** 첫 MVP에서 뺀다(사용자 답에 따라 조정):

- 가족·공개 공유, 소셜(팔로우·댓글·좋아요)
- 감정·기분 기록과 차트·통계
- 영상·음성·위치·지도 보기
- 연속 기록(streak)·알림 압박, 미기록 날 경고 표시
- 다중 일기장·태그·검색·내보내기(필요 시 후순위)
- 결제·마켓(§0 후속). 로그인 방식과 다중 사용자 여부는 §10 미정
- AI 기능 전체 — §7에서 B를 고르더라도 직접 작성 흐름(A)이 먼저 동작한 뒤 추가하는 것을 권고

## 7. AI 선택 표 — **[미정] 결정 대기**

최종 작성·정리 화면을 설계하고 제품으로 구현하기 전에 사용자 결정이 필요하다. 두 방식은 정리 화면의 구조가 다르다.
2026-11-02 사용자 요청에 따른 선택용 정적 시안은 직접 작성(A)을 가정으로 표시해 먼저 비교한다. 시안 게시가 A 선택이나 MVP 확정을 뜻하지 않는다.

| 기준 | (A) 사용자가 직접 하루 작성·정리 | (B) 기록에서 AI 초안 생성 + 사용자 수정 |
|---|---|---|
| 하루 정리 화면 | 순간 목록 옆 빈 편집기 | 생성 버튼·초안 표시·수정/재생성/폐기 상태 |
| 사용자 부담 | 직접 써야 함 | 낮음(검토·수정 중심) |
| "내 일기"라는 느낌 | 높음 | 문체가 내 것이 아닐 수 있음 |
| 데이터 경로 | 기기·서비스 안에 머묾 | 일기 내용(사진 포함 시 사진)이 AI 제공자로 전송될 수 있음 → 동의·보관 정책 필요 |
| 비용·운영 | 없음 | 호출 비용, 실패·지연 처리, 제공자 선택 |
| 품질 위험 | 없음 | 사실과 다른 내용 생성, 민감 내용 처리 |
| MVP 영향 | 최소 수직 슬라이스에 그대로 들어감 | A의 저장·편집 흐름 위에 추가 단계 |

**[권고]** MVP는 A로 시작하고, 정리 화면을 "초안 자리"를 나중에 넣을 수 있게 설계한 뒤 B를 후속 후보로 둔다. 단, 사용자가 AI 초안을 핵심 가치로 본다면 B를 MVP에 포함하고 §10의 데이터 조건을 먼저 정한다.

## 8. 사용자에게 중요한 질문 (최대 3개)

1. **Q1 첫 사용자·형식:** 처음엔 본인 혼자 쓰는 일기인가요? 순간 기록은 "짧은 글 중심(사진 선택)"과 "사진 중심(글 선택)" 중 어느 쪽인가요?
2. **Q2 하루 정리 방식:** 하루 정리를 (A) 직접 쓰기와 (B) AI 초안을 받아 고치기 중 무엇으로 시작할까요? B라면 일기 내용을 외부 AI 서비스에 보내도 되나요?
3. **Q3 공유 범위:** 첫 버전은 본인만 보기로 충분한가요, 아니면 가족 등 특정인 공유가 처음부터 필요한가요?

## 9. 수용 기준 초안 (A 기준, 사용자 답 뒤 갱신)

- [ ] 사용자는 오늘 화면에서 짧은 글 순간을 저장하고, 저장 시각과 함께 오늘 목록에서 즉시 본다.
- [ ] 사용자는 저장한 순간을 수정·삭제할 수 있다. **[확정]** 수정은 조각 하나의 글·이미지만 바꾸고 기록 시각·다른 조각·개수는 그대로다. 오늘·지난 날 모두 가능하고 취소하면 바뀌지 않는다.
- [ ] **[확정]** 사용자는 설정에서 기록 글꼴을 고르고 기본값으로 되돌릴 수 있다. 글꼴은 기록 본문(조각 글·하루 정리·편집 칸)에만 적용되고, 선택은 재접속 뒤에도 유지된다.
- [ ] **[확정]** 사용자는 자기 하루를 간단한 그리기·안전 영역 안 배치로 꾸밀 수 있다(세부 기준은 꾸미기 설계 뒤 추가).
- [ ] 사용자는 오늘의 순간들을 보면서 하루 정리 글을 작성·저장·수정할 수 있다(하루 1개).
- [ ] 사용자는 날짜를 골라 그날의 하루 정리와 순간을 시간순으로 다시 볼 수 있다. 기록 없는 날은 압박 없는 빈 상태를 보인다.
- [ ] 기록은 본인만 볼 수 있다(인증 방식은 미정).
- [ ] 새로고침·재접속 뒤에도 기록이 유지된다.
- [ ] 휴대폰 폭에서 순간 기록이 한 화면·한 번의 저장 동작으로 끝난다.
- [ ] 한국어 본문이 실제 렌더에서 읽기 좋게 보이고, 키보드 조작·색 대비 AA를 만족한다(조사 문서 확인 예정 항목).
- 사진(Q1)·AI 초안(Q2 B)·공유(Q3)를 포함하면 해당 수용 기준을 추가한다.

성공 기준(제품 가설): 첫 사용자가 1~2주 동안 대부분의 날에 순간을 남기고, 주 1회 이상 지난 날짜를 다시 본다. 측정 방법은 미정.

1. 메인 검토 → 사용자에게 §8 질문 → 이 문서 갱신(초안 표시 해제).
2. `docs/product/`에서 shaping·MVP 확정(공통 09 §2.1~2.3).

5. 구현 계획 `docs/plans/PLAN_<작업명>.md` → 구현·시험.
