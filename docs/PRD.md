## 2. 제품 정의

- **[확정]** "개인의 일상에서 순간을 기록하고 하루를 정리하여 스토리텔링을 만들어가는 감정정리 장소, pieceofdays".
  개인이 하루 중 사진과 짧은 메모를 남기고, 시간 정보를 바탕으로 회고하며, **AI가 그날의 이야기를 만들어 주는 곳**이다. 이야기는 날짜별로 다시 읽을 수 있어야 한다. 시간 정보의 구체적 의미는 §7에서 결정한다.
  (이력: 첫 초안의 "…일기장" 소개를 2026-11-02 "감정정리 장소"로 바꿨다. 기록·정리·스토리텔링의 흐름은 같다.)
- **[권고]** 핵심 단위: 순간(사진·짧은 메모와 시간 맥락) → AI 하루 이야기(그날을 돌아보는 스토리텔링) → 날짜별 다시 읽기.
- **[권고]** 차별점 가설: 긴 일기를 직접 완성하는 부담을 줄이고, 남긴 재료로 AI가 만든 이야기를 통해 하루를 돌아본다. 직접 쓴 한 줄은 보조 기록이며 AI 하루 이야기를 대체하지 않는다.

## 4. 핵심 여정: 사진·메모·시간 → AI 하루 이야기 → 날짜별 다시 읽기

| 단계 | 사용자 행동 | 결과 |
|---|---|---|
| 1. 순간 기록 | 실제 사진과 짧은 메모를 남김 | 하루를 돌아볼 재료가 계정에 저장됨 |
| 2. 시간과 회고 | 기록과 설정된 시간을 통해 하루를 돌아봄 | 시간의 의미를 확정한 뒤 입력·설정 흐름을 설계 |
| 3. AI 하루 이야기 | AI가 남긴 재료를 바탕으로 그날의 스토리텔링을 만듦 | 하루 이야기 확인. 생성 시작·보관·수정·재생성 동작은 설계 제안 단계 |
| 4. 날짜별 다시 읽기 | 날짜를 골라 하루 이야기와 원래 조각을 다시 읽음 | 지난 하루 회상 |

## 5. 최소 수직 슬라이스 후보와 첫 화면 후보

**[권고] 최소 수직 슬라이스:** 실제 계정에 사진을 업로드·저장 → 짧은 메모와 시간 맥락을 남김 → AI가 하루 이야기를 만듦 → 다음 접속에 날짜를 골라 이야기와 원래 조각을 다시 읽음. ‘설정된 시간’의 의미와 AI 데이터 조건을 확정한 뒤 세부 동작을 설계한다. 로그인·텍스트 CRUD는 이 흐름을 위한 기반이며 이들만으로 슬라이스를 완료하지 않는다.

| 첫 화면 후보 | 내용 | 장점 | 위험 |
|---|---|---|---|
| **(권고) 오늘** | 오늘의 사진·메모 조각 + AI 하루 이야기 진입 | 기록과 회고가 이어짐 | 생성 전·진행 중·실패·완료 상태 설계 필요 |
| 달력 | 월 달력에 기록 있는 날 표시 | 회상·쌓임이 보임 | 첫 사용 시 빈 화면, 기록까지 한 단계 더 |

기존 시각 방향은 D 선택을 따른다. 위 AI 회고 흐름은 아직 아트보드가 없으며, 기존 한 줄 편집기를 완성된 AI 화면으로 간주하지 않는다.

## 6. MVP 제외 제안

**[확정]** MVP에 넣는다: 사진·짧은 메모·시간 기반 AI 하루 이야기, 기록 CRUD(조각 추가·개별 수정·삭제), 날짜별 다시 읽기, 기록 글꼴 설정, 개인용 하루 꾸미기 기본(간단한 그리기·안전 영역 안 배치). AI 이야기의 편집·재생성 규칙은 별도 설계하며, 기존 조각 수정 요구와 구분한다.
**[확정]** 후속: 디자인 마켓·구매·제작자 정산. 첫 로그인 감정덩어리 지급 정책은 §0을 따르고, 지급 구현 단계와 마켓 사용 단계를 계획에서 구분한다.

**[권고]** 첫 MVP에서 뺀다(사용자 답에 따라 조정):

- 가족·공개 공유, 소셜(팔로우·댓글·좋아요)
- 감정·기분 기록과 차트·통계
- 영상·음성·위치·지도 보기
- 연속 기록(streak)·알림 압박, 미기록 날 경고 표시
- 다중 일기장·태그·검색·내보내기(필요 시 후순위)
- 결제·마켓(§0 후속). 공급자 간 계정 연결 방식은 §0 미정

## 7. AI 하루 이야기 — 핵심 확정, 동작·데이터 조건 미정

사진·짧은 메모·시간에서 AI가 하루 이야기를 만드는 것은 핵심이다. 직접 작성과 AI 중 하나를 다시 선택하는 질문은 두지 않는다. 기존 D 시안의 ‘하루 한 줄’은 당시 직접 작성 가정의 화면이며, 보조 기록으로 다룬다.

| 항목 | 현재 기준 | 남은 결정 |
|---|---|---|
| 입력 | 사진 + 메모 몇 줄 + 시간 | 사진 장수·크기, 글 길이, 필수 입력, 사진 내용을 AI가 분석하는 범위 |
| 설정된 시간 | 회고에 쓰이는 핵심 요소 | 순간별 시각인지, 매일 생성 시각인지, 둘 다인지. 자동 생성·알림을 확정한 것은 아님 |
| 이야기 | AI가 그날의 스토리텔링을 만듦 | 문체·길이·품질 기준, 생성 시작·실패·지연 처리 |
| 보관·편집 | 날짜별 다시 읽기를 위한 결과 보관이 필요 | **[권고]** 결과를 보관하고 원본 조각과 함께 제공. 사용자 수정·재생성·폐기 규칙은 제안·검토 단계 |
| 외부 전송 | AI 핵심 요구와 외부 전송 동의는 별개 | 제공자·모델, 글/사진 전송 범위, 동의·보관·학습 사용 여부 |
| 운영 | 실제 AI 연결이 필요 | 비용·호출 한도·자동 생성 트리거·중복 생성·출시 일정 |

**현재 미구현:** 실제 사진 업로드·보관, AI 하루 이야기 생성, 설정된 시간 기능. 정적 시안의 직접 그린 SVG 예시 이미지는 실제 사진 업로드나 사진 분석이 아니다. 상세 계획은 [PLAN_ai-daily-story-core](plans/PLAN_ai-daily-story-core.md)를 따른다.

## 8. 사용자에게 중요한 질문 (최대 3개)

1. **Q1 설정된 시간:** 순간마다 남기는 시각인가요, 매일 AI 이야기를 만드는 시각인가요, 둘 다인가요? 답 전에는 자동 생성을 확정하지 않는다.
2. **Q2 AI 데이터 조건:** 사진·메모 중 무엇을 AI에 전달할지, 외부 AI 전송에 동의할지, 보관·학습 사용 조건과 비용 한도를 어떻게 정할지 결정이 필요하다. 제공자·모델도 미정이다.
3. **Q3 첫 사용자·공유 범위:** 첫 사용 대상과 첫 버전의 본인만 보기 / 특정인 공유 범위를 정해야 한다.

## 9. 수용 기준 초안 (2026-11-10 핵심 반영)

- [ ] 사용자는 실제 사진을 계정에 업로드·저장하고 짧은 메모를 남긴다. 예시 이미지 선택만으로 충족하지 않는다. 입력 개수·상한·필수 여부는 세부 설계에서 정한다.
- [ ] ‘설정된 시간’의 의미를 사용자에게 확인하고 그 시간 정보를 기록·회고 흐름에 반영한다. 답 전에는 자동 생성 시각으로 간주하지 않는다.
- [ ] AI가 사진·메모·시간을 바탕으로 하루 이야기를 만들고 사용자가 읽을 수 있다. 사진 분석·전송 범위와 생성 시작 동작은 §7의 결정 뒤 검증 기준을 구체화한다.
- [ ] 사용자는 저장한 순간을 수정·삭제할 수 있다. **[확정]** 수정은 조각 하나의 글·이미지만 바꾸고 기록 시각·다른 조각·개수는 그대로다. 오늘·지난 날 모두 가능하고 취소하면 바뀌지 않는다.
- [ ] **[확정]** 사용자는 설정에서 기록 글꼴을 고르고 기본값으로 되돌릴 수 있다. 글꼴은 기록 본문(조각 글·하루 정리·편집 칸)에만 적용되고, 선택은 재접속 뒤에도 유지된다.
- [ ] **[확정]** 사용자는 자기 하루를 간단한 그리기·안전 영역 안 배치로 꾸밀 수 있다(세부 기준은 꾸미기 설계 뒤 추가).
- [ ] 사용자는 날짜를 골라 그날의 AI 하루 이야기와 원래 사진·메모를 다시 읽을 수 있다. 결과 보관 방식을 세부 설계하고 새로고침·재접속 뒤 유지됨을 검증한다. 기록 없는 날은 압박 없는 빈 상태를 보인다.
- [ ] **[권고]** 직접 쓰는 한 줄은 보조 기록으로 유지한다. AI 이야기 수정·재생성·폐기 동작은 확정 후 별도 수용 기준을 둔다.
- [ ] **[가정]** 기록은 본인만 볼 수 있다. Google·Kakao 로그인(§0 확정)의 세션으로 판정하며, 공유를 도입하면 권한 기준을 추가한다.
- [ ] **[확정]** 사용자는 계정 탈퇴를 요청할 수 있고, 30일 복구 기간이 지나면 삭제된다.
  - **[메인 기술·UX 결정]** 요청 즉시 접근을 차단하고, 기간 안의 복구는 명시적 확인으로만 한다(자동 복구 없음).
  - 수용 기준 세부는 [PLAN_account-lifecycle](plans/PLAN_account-lifecycle.md).
- [ ] 새로고침·재접속 뒤에도 기록이 유지된다.
- [ ] PC·휴대폰에서 사진·메모 입력, AI 이야기 확인, 날짜별 다시 읽기를 검증한다. 같은 계정의 자료를 다른 기기에서도 다시 불러온다.
- [ ] 한국어 본문이 실제 렌더에서 읽기 좋게 보이고, 키보드 조작·색 대비 AA를 만족한다(조사 문서 확인 예정 항목).
- 공유(Q3)를 포함하면 별도 수용 기준을 추가한다. 사진·AI는 이미 핵심 범위다. 실제 로그인·메모 저장만 제공하는 상태는 MVP 완료가 아니다.

성공 기준(제품 가설): 첫 사용자가 1~2주 동안 대부분의 날에 순간을 남기고, 주 1회 이상 지난 날짜를 다시 본다. 측정 방법은 미정.

## 11. 의존 순서

1. 2026-11-10 교정을 PRD·분석·shaping·MVP·스토리보드에 정렬한다. 미정 항목은 §8·§10에 남긴다.
2. ‘설정된 시간’의 의미와 AI 데이터 조건을 확인하고 [핵심 계획](plans/PLAN_ai-daily-story-core.md)에 입력·생성·보관·오류 동작을 구체화한다.
3. Next.js 구성과 **D 선택 완료**를 이어 사용한다. 기존 인증·저장 계획은 기반 단계로 연결한다.
4. 사진·시간·AI 회고 흐름의 스토리보드 → 화면 설계·브리프 → D 기반 아트보드·핸드오프를 설계·검토한다. 기존 직접 작성 시안이 이 화면을 대신하지 않는다.
5. 검토된 구현 계획 → 구현·시험. 배포·외부 전송 권한과 출시 일정은 문서 정렬만으로 확정되지 않는다.
