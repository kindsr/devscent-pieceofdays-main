# AI 하루 이야기 읽기·생성 아트보드 (시안 D 이어 쓰기)

- **상태:** 정적 아트보드다. 합성 예시만 쓰며 **배포하지 않는다.** `frontend/public/`에 사본이 없어 개발 도메인에는 나타나지 않는다. 실제 생성·저장·로그인·네트워크 요청은 없다.
- **파일:** [`index.html`](index.html) 하나다. D 정본 [`../concepts/d-warm-pieces/style.css`](../concepts/d-warm-pieces/style.css)를 상대 경로로 불러오고, 이야기 영역 규칙만 페이지 안 `<style>`에 더한다. 외부 글꼴·CDN·iframe·fetch는 없다.
- **보는 법:** 저장소 체크아웃에서 `docs/design/story/index.html`을 브라우저로 직접 연다. 맨 위 점선 줄(아트보드 도구)에서 이야기 상태, 본문 길이(보통 또는 최대 2000자), 기록 글꼴을 바꾼다. 이 도구 줄은 제품 화면에 옮기지 않는다.
  - `보기`에서 `S2 읽기 7상태 (보존)`(기본, 아래 §1~§6)와 `S3 생성 계약`(§7)을 고른다. S3 보기에서는 화면(날짜·설정), 이야기, 생성 상태, 회고 시각을 따로 고른다.
- **기준:** 선택안 D 토큰·상단 셸·버튼·조각·하루 한 줄([디자인 핸드오프](../README.md))과 [S1 저장 계획](../../plans/PLAN_ai-daily-story-storage.md)의 `StoryDay` DTO다. S3 보기는 [실제 생성 계획](../../plans/PLAN_ai-story-live-generation.md) §3·§5의 `StoryGenerationView`와 화면 계약을 따른다. 새 디자인 3안을 만들지 않았다. 기존 [핸드오프](../README.md) §1의 "AI 하루 이야기 아트보드 없음" 행은 메인이 통합 단계에서 갱신한다(이 작업에서는 고치지 않음).

## 1. 배치 (메인 결정 2026-11-11)

| 폭 | 순서 |
|---|---|
| 1100px 이상 | 날짜 머리 → **이야기(메인 열 전체 폭, 본문 최대 64ch)** → 기존 `.with-side`(조각 4열 + 오른쪽 300px 하루 한 줄) |
| 768px | 날짜 머리 → 이야기 → 하루 한 줄 → 조각 3열 |
| 375px | 날짜 머리 → 이야기 → 하루 한 줄 → 조각 2열 |

- 2000자 본문을 오른쪽 300px 열에 넣지 않는다. 읽기 폭은 64ch로 제한하고, 줄바꿈과 문단(`pre-wrap`)을 보존한다. 접기는 없다.
- 이야기는 조각 목록 위에 둔다. 하루의 결과물을 먼저 읽고, 그 아래에 원본을 그대로 둔다.
- 하루 한 줄(사용자가 직접 쓴 글)은 기존 위치와 내용을 보존한다. 아트보드에서는 제목을 "하루 한 줄 · 내가 쓴 글"로 적어 생성 글과 구분했다. 실제 제목 문구를 바꿀지는 S2 구현 때 메인이 정한다.

## 2. 생성 글과 원본 구분

- 이야기 영역 제목은 "AI 하루 이야기"다. 본문 위에 출처 문장 한 줄을 둔다: "AI가 이날 조각의 메모로 쓴 글이에요. 원본 조각과 하루 한 줄은 아래에 그대로 있어요. · 만든 시각".
- 조각 목록 위에는 "이날의 조각 — 내가 남긴 원본 메모예요"를 둔다.
- 이야기에는 수정·삭제 동작이 없다(정책 미정).
- uncodixfy 기준에 따라 eyebrow, `<small>` 머리, pill 배지, 새 그림자·그라데이션, 장식 문구를 쓰지 않았다. 상태는 문장 한 줄로 말한다.

## 3. 상태

| 도구 값 | 근거 | 표현 | 동작 |
|---|---|---|---|
| 준비 전 `unavailable` | **S1 DTO 그대로**(`generation: "unavailable"`). 현재 S1·S2의 실제 상태 | "AI 하루 이야기는 아직 준비 중이에요…" | 버튼 0. 미준비를 버튼 뒤 실패나 성공으로 위장하지 않는다 |
| 최신 `current` | S1 DTO `state: "current"` | 출처·만든 시각 + 본문 | 0 |
| 조각이 바뀐 뒤 `outdated` | S1 DTO `state: "outdated"` | "이 이야기를 만든 뒤 조각이 바뀌었어요…" + 본문 유지. 예시는 조각 1개가 추가된 상태다 | `지금 조각으로 새로 만들기`(**생성이 가능해진 뒤에만**) |
| 조각을 모두 지운 뒤 `deleted` | S1 DTO `outdated`이고 조각 0, `inputRevision: null` | "이 날의 조각을 모두 지웠지만, 이전에 만든 이야기는 남아 있어요." + 본문, 조각 자리는 "이 날의 조각이 없어요." | 0 |
| 없음 `none` | S1 DTO `state: "none"`. 버튼은 **후속 계약**(0006 동의·예약·비용 한도 통과 뒤) | "회고 시간(20:00)이 되면… 지금 만들 수도 있어요." + `회고 시간 바꾸기` 링크 | `지금 이야기 만들기` → 만드는 중 |
| 만드는 중 `pending` | **후속 계약 예정**(PG 예약 행 + one-shot worker, PLAN §4). S1에는 없다 | "이야기를 만드는 중이에요. 이 화면을 떠나도 괜찮아요…" | 버튼 비활성(`aria-disabled`). spinner·애니메이션 없음 |
| 실패 `error` | **후속 계약 예정**(S2 action 오류: `unavailable`·`timeout`·`invalid_output` 등) | `role="alert"` 고정 문구: "이야기를 만들지 못했어요. 남긴 조각과 이전 이야기는 그대로예요." 원문 오류는 0 | `다시 시도` → 만드는 중 |

- `none`·`pending`·`error`와 "새로 만들기"·"다시 시도" 버튼은 **아직 계약이 없는 후속 상태**다. S1 제품에는 생성 진입점이 없다(`getStoryGenerator()`는 항상 null). 이 화면은 그 후속 설계를 미리 보여 줄 뿐이며 구현 완료가 아니다.
- 아트보드에서 버튼을 누르면 "만드는 중"으로만 바뀐다. 자동으로 최신 상태가 되는 가짜 성공은 없다.
- 오류 세부(`conflict`이면 "조각이 바뀌어 다시 불러올게요" + `다시 불러오기`, `not_signed_in`이면 기존 로그인 안내, `input_too_large`·`invalid_input` 문구)는 S2 action 계약이 정해질 때 이 표에 더한다.
- 조각 0이고 이야기도 0인 날은 이야기 영역을 보이지 않는다(기존 빈 날 문구 유지). 아트보드에는 따로 그리지 않았다.
- **S3 이후:** 위 표의 `none`·`pending`·`error`와 그 버튼 문구(`지금 이야기 만들기`·`지금 조각으로 새로 만들기`·`다시 시도`)는 S2 당시의 후속 예고다. 실제 계약은 §7이 대체한다. 비교를 위해 S2 보기에 그대로 보존한다.

## 4. 회고 시간·기록 글꼴

- 회고 시각은 계정 설정값을 그대로 보여 준다(기본 20:00, 서울). 날짜 머리의 `설정(회고 시간·글꼴)`과 없음 상태의 `회고 시간 바꾸기`는 실제 앱에서 `/settings`로 간다. 아트보드에서는 D 설정 시안으로 연결된다.
- 이야기 본문은 사용자가 고른 기록 글꼴(`--font-record`)을 따른다. 조각 글·하루 한 줄과 같다. 제목·상태 줄·버튼은 D UI 글꼴이다.

## 5. 접근성

- 영역은 `<section aria-labelledby>`와 `h2`다. Tab 순서는 상단 → 날짜 머리 링크 → 이야기 버튼·링크 → 원본 순서다. `:focus-visible`은 D의 3px `--focus`다.
- 상태가 바뀌어도 포커스를 옮기지 않는다. `aria-live="polite"` 영역 하나로 알리고, 오류만 `role="alert"`다.
- 생성 중 버튼은 `aria-disabled`로 남겨 포커스로 상태를 읽을 수 있게 했다. 모든 터치 대상은 44px 이상이다(D 버튼 규칙).
- 본문은 `textContent`로 넣어 HTML로 해석하지 않는다. 색은 D 표의 AA 조합만 쓴다(오류 `#8E2A12`는 surface 대비 8.18).

## 6. 한계와 후속

- 합성 예시: 날짜(2026-11-02), 조각 4~5개, 하루 한 줄, 이야기 본문은 모두 만든 예시다. 이야기 본문은 조각 메모에 있는 일만 이어 쓰도록 작성했다. 실제 AI 출력이 아니다. 사진 조각은 넣지 않았다. S3에서는 전송 범위(메모 원문 + 사진 512px 사본)를 §7 고지문으로 표시한다.
- 시각 확인: 이 작업에서는 브라우저·스크린샷을 실행하지 않았다. 375·768·1440 캡처는 후속 CI 또는 실제 D 컴포넌트(`DailyStory`)에서 메인이 배정한다.
- 이 파일은 제품 코드가 아니다. 실제 화면을 흉내 내는 고정 성공 상태를 앱에 넣지 않는다.
- 미정: 이야기 수정·삭제 정책, 조각 0인 날로 들어가는 경로(달력에서 누를 수 없는 칸). 외부 전송 동의 문구·위치는 §7에 S3 초안으로 두었다(최종 문구는 메인 통합 때 확정).

## 7. S3 생성 계약 보기 (PLAN_ai-story-live-generation)

### 7.1 설정 화면 — AI 하루 이야기 동의(`#story-ai`)

- 기존 설정 화면(회고 시간·기록 글꼴·계정)에 D `.settings` 영역 하나를 더한다. id는 `story-ai`이고, 날짜 화면의 미동의 링크가 이 id로 온다.
- 고지(사실만 쓴다):
  - 켜면 그날 남긴 메모 원문과 사진의 512px 사본을 Anthropic의 Claude API로 보내 이야기를 만든다.
  - 보낸 자료는 회수할 수 없다. 끄면 그 뒤로는 새로 보내지 않는다.
  - 저장할 때마다 새 동의로 기록하고, 그 전에 맡긴 요청은 보내지 않는다(동의 epoch, 계획 §4.5).
  - 공급자 보존 기간·법률 적합성은 확인하지 않았으므로 쓰지 않는다.
- 체크 두 개는 **둘 다 기본 꺼짐**이고 서로 독립이다.
  - `직접 만들기 허용`: 설명은 "날짜 화면에서 ‘AI 이야기 만들기’를 누를 때만 보내요. 하루 3번까지예요."
  - `회고 시간(현재 HH:MM)에 자동으로 만들기`: HH:MM은 계정 회고 시각이며 없으면 20:00이다(서울). 설명은 "매일 회고 시간이 지나면 한 번 만들어요. 그날 조각이 없으면 만들지 않아요."
  - 체크의 접근 이름은 굵은 이름 줄만 쓰고, 설명은 `aria-describedby`로 연결한다(시험의 정확한 이름과 맞춘다).
- 저장 버튼은 `저장`이다. 아트보드에서는 안내 한 줄과 생성 상태 이름만 바뀐다. 실제 저장·전송은 없다.

### 7.2 날짜 화면 — 이야기 × 생성 상태

| 생성 상태 | 표시 | 버튼·링크 |
|---|---|---|
| `unavailable`(키 없음), `off`(미동의), 동의 철회 뒤 `off` | 이야기가 없으면 기존 문구 "AI 하루 이야기는 아직 준비 중이에요. 남긴 조각은 그대로 저장돼요."(S2와 같음). 이야기가 있으면 그 글만 | 버튼 0. `off`에서 만들 수 있는 날이면 `AI 이야기 설정` 링크(`/settings#story-ai`). 기존 정확한 `/settings` 링크(회고 시간 줄)는 1개로 유지 |
| `ready` | 기존 이야기 표시 그대로 | **조각이 있고 이야기가 없음 또는 바뀐 뒤일 때만** `AI 이야기 만들기`. 최신 이야기 또는 조각 0이면 버튼 0 |
| `queued` / `running` | "AI 이야기를 만드는 중이에요."(queued는 "만들 차례를 기다리고 있어요." 추가)와 "화면은 저절로 바뀌지 않아요. 잠시 뒤 새로고침해서 확인해 주세요." | 버튼 0. 명시 `새로고침` 링크(실제 앱은 같은 날짜 경로). polling·타이머·spinner 0 |
| `failed`(사진) | `role="alert"` "사진을 읽지 못해 만들지 못했어요. 남긴 조각과 이전 이야기는 그대로예요." | canRetry이고 만들 수 있는 날이면 `AI 이야기 만들기` |
| `failed`(그 밖) | `role="alert"` "이야기를 만들지 못했어요. 남긴 조각과 이전 이야기는 그대로예요." 원문 오류 0 | 위와 같음. canRetry가 아니면(오늘 한도 소진) "오늘은 더 만들 수 없어요."와 버튼 0 |
| `limited` | "오늘은 더 만들 수 없어요. 직접 만들기는 하루 3번까지예요." | 버튼 0 |

- 이야기 상태(none·current·outdated·조각 0)는 S2와 같은 문장·본문 배치를 쓴다. 생성 상태 문구는 그 아래, 회고 시간 줄 위에 둔다.
- 버튼을 누르면 아트보드는 `queued`로만 바뀐다(실제 앱: Server Action이 job 1건을 맡긴다). 자동으로 성공 상태가 되는 흐름은 없다. 결과는 사용자가 새로고침해서 본다.
- `skipped` job(입력 없음·이미 최신)은 화면 상태가 아니다. 그날의 현재 설정에 따라 `ready` 또는 `off`로 보인다(오류 이름을 보여 주지 않는다).
- 접근성: §5를 그대로 따른다. 상태 변화는 polite 알림 하나로 전하고, 실패만 `role="alert"`다. 포커스는 옮기지 않는다. 모든 버튼·링크·체크는 44px 이상이다.

### 7.3 한계

- 합성 도구다. 실제 API·worker·cron·DB·사진 저장소 연결은 없고 브라우저·스크린샷 검증은 이 작업에서 하지 않았다. 3폭 실제 확인은 S3 E2E(`story-generate.spec.ts`)의 캡처가 맡는다.
- 문구는 S3 RED가 고정한 화면 계약(버튼 `AI 이야기 만들기`, `만드는 중이에요`, 사진 실패, `오늘은 더 만들 수 없어요`, 두 체크 이름, `story-ai`)과 맞춘 초안이다. 설명 문장·고지 세부는 메인 통합 때 확정한다.
