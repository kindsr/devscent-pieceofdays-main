## 1. 단계 1 — MVP (기록 + 개인용 꾸미기 라이트)

범위:

- 기록: 조각(순간) 작성·**수정**·삭제, 하루 한 줄 정리 작성·수정, 날짜별 보기(D의 오늘/모아보기/특정 날), 첫날 빈 상태.
- 계정: 로그인, 본인 기록만 접근. 모든 행에 `user_id`(소유자) 저장.
- 카피: 확정 문구 "개인의 일상에서 순간을 기록하고 하루를 정리하여 스토리텔링을 만들어가는 감정정리 장소, pieceofdays".
- [확정] 폰트: `font_key` 선택(허용 목록 2~3개, 기록 본문에만 적용).
- [확정] 꾸미기 라이트(구조 문서 §3.3): 기본 스티커를 슬롯 안전 영역에 배치, 그림 칸 펜(굵기 3·D 토큰 색), 획 단위 지우개, 실행 취소/다시 실행, 개인 저장(`DesignVersion` private) → 적용 → 기본으로 되돌리기. 본인 그림 업로드 포함 여부는 [미정].
- [제안] 감정덩어리 최소 접점: `CreditAccount`, append-only `EmotionLedger`, 첫 로그인 +10 지급 1종. 사용처가 없으므로 잔액 화면 노출은 [미정]. 사용자가 빼면 단계 3에서 같은 `grant_key`로 소급 지급한다(구조 문서 §6.2).

수용 기준:

- [ ] 조각을 저장하면 시각과 함께 오늘 목록에 즉시 보인다. 수정·삭제 결과는 새로고침 뒤에도 유지된다.
- [ ] 다른 사용자의 조각·하루 정리·개인 디자인 ID로 요청하면 거부된다. 존재 여부도 드러내지 않는다.
- [ ] 폰트를 바꾸면 조각 글·한 줄·입력란만 바뀌고, 상단·탭·버튼·날짜 제목은 그대로다. 허용 목록 밖 값은 저장되지 않는다. 꾸미기 적용·리셋은 폰트를 바꾸지 않는다.
- [ ] 꾸미기를 적용해도 D의 레이아웃·색 토큰·UI 서체·터치 대상·focus 순서가 기본 D와 같다(시각 비교와 접근성 트리 비교로 확인).
- [ ] 펜 획과 스티커는 그림 칸·슬롯 밖으로 나가지 않으며, 375/768/1440px에서 텍스트 상자·버튼과 겹치지 않는다.
- [ ] 실행 취소·다시 실행이 배치·펜·지우개 모두에 동작한다. 저장 후 새로고침하면 마지막 저장 상태가 보인다.
- [ ] manifest 오류가 나거나 에셋을 불러오지 못하면 기본 D로 렌더되고, 기록 기능은 정상으로 동작한다. "기본으로 되돌리기" 한 번이면 기본 D로 돌아간다.
- [ ] (제안 포함 시) 첫 로그인 사용자의 원장에 `first_login_grant` +10이 정확히 1행 생긴다.
- [ ] D 기준 375/768/1440px에서 수평 넘침이 없고, 터치 대상은 약 44px이며, 키보드로 조작할 수 있고, 대비는 AA를 만족한다. 편집기에도 키보드로 저장·취소·리셋할 수 있는 경로가 있다.

TDD 필수 경계(테스트를 먼저 쓴다):

- 소유권 검사: 기록과 개인 디자인을 조회·변경하는 모든 경로.
- manifest 스키마 검증: 범위 밖 좌표, 모르는 슬롯, 허용되지 않은 색·굵기, 획·점 수 상한, 남의 에셋.
- 렌더러 fallback, 펜 칸 clamp.
- 편집기 명령 기록: 실행 취소·다시 실행의 순서와 상한.
- `font_key` 허용 목록 검증.
- (제안 포함 시) 첫 로그인 지급 멱등: 같은 사용자의 로그인 처리를 실제 DB에서 병렬 연결로 **동시에 N회** 실행해도 원장 1행·잔액 10. 원장에는 UPDATE/DELETE 경로가 없고, 잔액 사본은 `SUM(delta)`와 같아야 한다.

실패 사례(테스트 포함): 로그인 콜백 중복, 두 기기에서 동시 첫 로그인, 지급 트랜잭션 중간 실패(원장·잔액 모두 남지 않음), 수정 중 다른 탭에서 삭제된 조각, 허용되지 않은 폰트 키, 두 기기에서 같은 디자인을 동시에 저장(새 버전 2개가 생기고 마지막 적용이 이기는 동작을 [권고]), 저장 도중 연결 끊김, 거대한 획 데이터.

마이그레이션·복귀: 첫 스키마 생성. 배포 전 dev DB에서 적용→되돌리기→재적용을 확인한다. 운영 DB는 dev와 분리한다. 꾸미기 기능을 끄면 `applied_design_version_id`를 무시하고 기본 D로 렌더한다. 이렇게 하면 데이터를 보존한 채 즉시 복귀할 수 있다. 원장 테이블은 되돌릴 때도 데이터를 지우지 않는다(백업 후 진행).

비목표: 마켓 게시·구매, 사용자 간 정산, 감정덩어리 사용처, 전문 드로잉 도구(자유 색·브러시·레이어·픽셀 지우개), 사진 외 미디어, AI 초안(PRD §7 결정 전), 공유, 감정 통계.

## 2. 단계 2 — 꾸미기 확장 (후속)

의존: 단계 1. 본인 그림 업로드를 MVP에서 뺐다면 여기서 넣는다. 그 경우 이미지 저장소(서비스 전용 버킷)와 업로드 검증·저작권 정책 초안이 필요하다([미정] 해소).

범위 후보: 본인 그림 업로드·검증, 슬롯 v1 5종 전체, 전문 드로잉 도구 일부(범위는 [미정]), 개인 버전 이력 화면.

수용 기준: 단계 1의 꾸미기 기준을 모두 유지하고, 업로드한 에셋도 같은 검증과 fallback을 통과해야 한다.

TDD 필수 경계: 업로드 검증(확장자 위조, 과대 해상도, 메타데이터 제거), 기록 사진과 에셋의 저장 위치·권한 분리.

실패 사례: 위조 PNG, 거대 이미지, 삭제된 에셋 참조, 이전 `schema` manifest.

마이그레이션·복귀: 에셋 테이블·버킷 접두어만 추가하고 기록 테이블은 바꾸지 않는다. 업로드 기능을 끄면 기본 스티커만 남는다.

## 3. 단계 3 — 마켓 + 1개 구매 + 제작자 적립 (후속)

의존: 단계 1·2, 미정 정책 결정(제작자 지급 조건, 판매 중단 후 사용, 신고·검수, 환불·탈퇴).

범위: 개인 디자인 게시(버전 고정, 게시 전 샘플 하루 미리보기 확인), 목록·상세(샘플 하루만), 구매(구조 문서 §6.3), 보유 목록·적용, 제작자 적립 표시. 단계 1에서 원장을 넣지 않았다면 이 단계의 마이그레이션에서 소급 지급한다.

수용 기준:

- [ ] 구매 1건에 구매자 −1, 제작자 +1, `Purchase`·`Entitlement` 각 1행이 한 트랜잭션으로 생긴다(권고 규칙).
- [ ] 같은 구매 요청을 재시도하거나 더블클릭해도 결과는 1건이다.
- [ ] 이미 보유한 디자인과 본인 디자인은 차감 없이 적용된다.
- [ ] 잔액 0에서 구매하면 아무 행도 생기지 않고 부족 안내가 나온다.
- [ ] 재적용·미리보기·버전 갱신은 원장을 바꾸지 않는다.
- [ ] 마켓 화면·썸네일에 기록 원문·사진이 나오지 않는다.

TDD 필수 경계: 구매 트랜잭션 전체(실제 DB). 동시성 시나리오:
- 잔액 1인 사용자가 서로 다른 디자인을 동시에 2건 구매하면 1건만 성공한다.
- 같은 디자인을 동시에 구매해도 권리는 1행만 생긴다.
- 두 사용자가 서로의 디자인을 동시에 구매해도 교착이 일어나지 않는다.
- 썸네일 입력에는 기록 데이터 경로가 없다.

실패 사례: 제작자 +1 삽입 실패(전체 롤백), 판매 중단 직후 구매, 탈퇴한 제작자, 원장과 잔액 사본 불일치 감지.

마이그레이션·복귀: 마켓 테이블을 추가한다. 소급 지급은 `grant_key` 유일 제약 덕분에 다시 실행해도 안전하다. 문제가 생기면 마켓 화면·구매 경로만 끄고 원장은 보존한다(정정은 반대 부호 행으로).

비목표: 현금 충전·환전, 가격 차등, 리뷰·랭킹·소셜.

## 4. 단계 4 — 추가 사용처 [미정]

감정덩어리의 다른 사용처가 정해지면 `reason`을 추가하고 단계 3의 트랜잭션 패턴(잠금 순서·멱등 키·잔액 검사)을 재사용한다. 사용처가 정해지기 전에는 설계하지 않는다.

## 5. 검증 공통

- 단위·통합 테스트는 PR 검사에서 실행한다. 원장·구매·지급의 동시성 테스트는 모의 객체가 아닌 실제 DB 컨테이너로 한다.
- 화면: 375/768/1440px 브라우저 확인, 키보드·스크린리더 기본 점검, 꾸미기 적용 전후 비교, 휴대폰 터치로 펜 입력 확인.
- 배포·운영 확인은 메인 통합 단계에서 기존 dev→main 절차를 따른다. 이 계획은 배포 경로를 바꾸지 않는다.
